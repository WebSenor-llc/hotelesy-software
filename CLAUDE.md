## What Hotelesy is
Multi-tenant hotel management SaaS at `/Users/shubhamsoni/Sites/hotelesy`. Built on **Laravel 11.51 + Livewire 4.3 + MySQL** for cloud, **Laravel 11.51 + Livewire 4.3 + SQLite** for desktop.


## Critical environment quirks

### PHP version is locked to 8.2.30
- `composer config platform.php 8.2.30` is set on this project
- DO NOT change it without first installing PHP 8.4 via Herd
- An earlier session set `platform.php=8.4` then ran `composer update --with-all-dependencies` which broke everything because real PHP was still 8.2 — required full rollback via `composer remove nativephp/electron && composer update --with-all-dependencies` with platform pinned back to 8.2.30
- **Lesson:** treat `composer config platform.php` as a real PHP upgrade, not a knob to flip

### Cloud and desktop must coexist on the same Mac
- `DesktopServiceProvider` namespaces session storage (`storage/framework/sessions-desktop/`), session cookie name (`hotelesy_desktop_session`), and cache prefix to avoid collisions with the cloud build
- Both can run simultaneously (cloud at `hotelesy.test`, desktop at `127.0.0.1:8001`) without stomping on each other's logins
- **Never run** `php artisan config:cache` or `route:cache` while developing both — caches are shared between the two modes via `bootstrap/cache/`

### MySQL-only DDL must be SQLite-aware
Three migrations use `ALTER TABLE ... MODIFY COLUMN ENUM(...)` which SQLite can't parse. They guard with `if (DB::connection()->getDriverName() !== 'mysql') return;`:
- `2026_05_07_300002_extend_folio_charge_categories.php`
- `2026_05_07_400001_relax_tax_invoice_state_code.php`
- `2026_05_07_700001_extend_license_billing_cycle_enum.php`

Any future enum-altering migration must do the same guard.

## Cloud-side license-server API (reachable when cloud is up)

Public endpoints in `routes/api.php`:
- `POST /api/desktop/activate` — first activation (binds machine fingerprint to license key)
- `POST /api/desktop/validate` — phone-home re-validation
- `POST /api/desktop/deactivate` — release seat for activation elsewhere

Backed by `app/Http/Controllers/Api/Desktop/LicenseServerController.php`. Accepts both `license_key`/`activation_key` and `hostname`/`host` parameter names for flexibility. Response includes both nested `license.{...}` and top-level fields so the desktop client can read either shape.

## Distribution strategy for the desktop edition

Three options were discussed for shipping the offline build to non-technical hoteliers:

1. **NativePHP** — cleanest. Bundles PHP runtime + app + Electron in `.dmg`/`.exe`. **Blocked** until PHP is upgraded to 8.3+ on the build machine (do via Herd → Settings → PHP → toggle 8.4).

2. **Bundle portable PHP yourself** — works today on PHP 8.2. Use [static-php.dev](https://static-php.dev) binary + project files + launcher script wrapped into a `.app` bundle. ~2 hours of build script work. Recommended path if shipping this week.

3. **Require Herd on customer's Mac** — give customer a folder + 5-step PDF. Lowest dev effort, highest customer effort, only viable for technical hoteliers.

The Path B launcher in `desktop-launcher/` is dev-only (assumes Mac has PHP installed). It is NOT a customer installer.

## Conventions

- **Indian context:** all user-facing prices in INR with `₹` symbol, dates in `DD MMM YYYY` format, GST default state code `08` (Rajasthan), HSN `996311` for room services
- **No emoji in production UI** unless explicitly requested by Piyush
- **Auto-login flows** must call `session()->regenerate()` immediately after `auth()->login()`
- **Multi-tenant queries** that need to bypass tenant scoping must use `app(TenantContext::class)->bypass(fn() => ...)` — but inside the bypass closure, `BelongsToTenant` auto-fill is also suppressed, so `tenant_id` must be set manually on inserts
- **Deprecated patterns** that have caused bugs in this codebase: typed Livewire properties without `(string)` / `(float)` casts on null DB values; `Route::post` aliases that bypass `LoginController`; missing `SESSION_DOMAIN` causing cookie rejection on subdomains
